# 微信支付 / 手机号 / 储值 上线配置清单

> 本文是**商家侧/运营侧**要做的配置与资质清单。代码与开关已就绪，
> 按本文逐项配好即可上线；配置项都在「管理端 → 系统配置」里，无需改代码。

## 一、微信支付（订单在线支付 + 储值充值共用）

两条链路共用同一套商户参数：

| 链路 | 场景 | 下单接口 | 回调 |
|---|---|---|---|
| Native 扫码 | H5 顾客端扫收款码 | `/v3/pay/transactions/native` | 同一个 notify_url |
| JSAPI | 小程序内直接调起微信支付 | `/v3/pay/transactions/jsapi` | 同一个 notify_url |

储值充值与订单支付**共用同一个回调地址**，后端按单号前缀分流：`R` 开头 = 充值单，`D` 开头 = 订单。

### 管理端要填的配置（系统配置 → 在线支付）

| 配置项 | 说明 | 常见坑 |
|---|---|---|
| 微信支付开关 `wxpay_enabled` | H5 收款码之外的自助在线支付总开关 | 关闭时顾客只能扫码/前台结账 |
| **小程序内支付 `wxpay_jsapi_enabled`** | 小程序里直接调起微信支付；**储值充值也依赖它** | 关闭时「微信支付」「充值」入口都不出现 |
| 微信商户号 `wxpay_mchid` | mch 开头的 10 位数字 | — |
| 微信 AppID `wxpay_appid` | **必须是小程序的 AppID** | 填成公众号 AppID 时 Native 能跑、JSAPI 必拒付 |
| APIv3 密钥 `wxpay_apiv3_key` | 32 位，商户平台 → 账户中心设置 | 敏感项，保存后回显 `******`，留空表示不修改 |
| 商户证书序列号 `wxpay_serial_no` | 商户 API 证书的序列号 | 与私钥必须是同一张证书 |
| 商户私钥路径 `wxpay_private_key_path` | `apiclient_key.pem` 在**服务器上**的路径 | 服务器读不到就全部下单失败 |
| 平台证书路径 `wxpay_platform_cert_path` | 回调验签用（或配置公钥模式 `wxpay_pubkey_*`） | 路径错误表现为「回调验签失败」 |
| 回调地址 `wxpay_notify_url` | 必须 **HTTPS + 公网可达**，形如 `https://你的域名/api/customer/pay/notify/wxpay` | 用内网地址时支付成功但永远不入账 |

### 商家在微信商户平台要做的

1. 开通 **JSAPI 支付**产品（Native 与 JSAPI 是两个产品，都要开通）。
2. 在「开发配置」里确认支付授权目录 / 回调域名与 `wxpay_notify_url` 一致。
3. AppID 与商户号的绑定关系里，必须包含**这个小程序的 AppID**（否则 JSAPI 下单报「appid 与 mchid 不匹配」）。

## 二、手机号快速验证（getPhoneNumber）

| 事项 | 说明 |
|---|---|
| 主体资质 | 小程序必须是**企业认证主体**，个人主体没有这个组件 |
| 开通组件 | 小程序后台 →「获取手机号快速验证组件」申请开通，**按次收费**（以微信当期价格为准） |
| 隐私声明 | 「用户隐私保护指引」必须声明采集**手机号**（此前只声明 openid/昵称/头像的话要更新），否则真机上拿不到 code |
| 计费影响 | 每次成功换取都计费；前端只在用户点按钮时拉起授权，取消不计费 |

行为约定（代码已内置）：

- 绑定失败**绝不影响登录/点餐**（手机号是增强信息）；
- 同一手机号全店只能属于一个会员，重复绑定幂等成功；
- 接口与日志只输出脱敏串（`139****0001`），完整号码仅存 `tb_customer_identity`（provider=`phone`）。

## 三、储值

| 配置项 | 说明 |
|---|---|
| **储值自助充值 `wallet_recharge_enabled`** | 默认**关**。开启后顾客钱包页出现充值入口；关闭只隐藏充值入口，**不影响已有余额的消费与退款** |
| 小程序内支付 `wxpay_jsapi_enabled` | 充值走 JSAPI，未开通时充值入口同样不出现（两开关取与） |

金额与口径（代码内置，无配置项）：

- 只收**整数元**，单笔 1 ~ 10000 元；
- 余额支付在同一个事务里完成「扣余额 + 支付流水 + 订单入账」；
- 充值入账幂等（微信重发通知不重复加钱），金额不一致绝不入账；
- 余额支付订单的退款 = 同步退回储值余额，不走渠道退款；
- 后台调账（赠送/扣减）必须填原因，操作人写入流水并可审计。

## 四、上线检查清单（逐项勾）

- [ ] 微信商户号已开通 **JSAPI 支付**，且与小程序 AppID 完成绑定
- [ ] `wxpay_appid` = 小程序 AppID；`wx_app_secret` 已填（会员/充值/JSAPI 都靠它）
- [ ] 商户证书序列号 + 私钥路径 + APIv3 密钥 + 平台证书路径已配置，且服务器进程可读
- [ ] `wxpay_notify_url` 为 HTTPS 公网地址，且从公网可达（`curl -I` 不超时）
- [ ] `wxpay_enabled` / `wxpay_jsapi_enabled` 已开启；要自助充值再开 `wallet_recharge_enabled`
- [ ] 「用户隐私保护指引」已声明：openid、昵称、头像、**手机号**
- [ ] 小程序后台已开通「获取手机号快速验证组件」（企业主体）
- [ ] 真机回归：小程序内支付一笔 → 后台看到入账；钱包充值一笔 → 余额变化 + 流水出现「充值」；余额支付一笔 → 订单已支付且流水渠道为「储值余额」；对该单退款 → 余额退回
